Three sibling test projects mirror the production layering: `Ecommerce.Domain.Tests` exercises pure domain logic (`Order`, `InventoryItem`) with no infrastructure dependencies; `Ecommerce.Application.Tests` targets command handlers (`CheckoutCommandHandler`, `ReserveInventoryHandler`, `DispatcherReserveInventoryHandler`) by wiring an in-memory `ApplicationDbContext` plus `IdempotencyService`; `Ecommerce.IntegrationTests` references the API project to exercise full request paths against an in-memory EF Core database. Each test project is a self-contained .NET SDK-style test project (`IsTestProject=true`) referencing only the layers it needs, keeping dependency direction strictly downward from tests → production code. Tests use per-test `DbContextOptionsBuilder` with a unique GUID-scoped in-memory database so each `[Fact]` runs in isolation without shared state.
